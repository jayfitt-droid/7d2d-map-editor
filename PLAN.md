# Plan: 7 Days to Die map editor (Windows desktop app)

## Context
Research showed that a 7D2D world is just a folder of files: `dtm.raw`, `biomes.png`, `splat3.png`, `splat4.png`, `radiation.png`, `prefabs.xml`, `spawnpoints.xml`, `map_info.xml` and `main.ttw`. The game processes this folder itself on first load. So a standalone editor can produce playable maps without the in-game generator (RWG).

Decisions so far:
- **Public release.**
- **C# + WPF.**
- **v1 supports both** editing an existing world and authoring one from scratch.

`C:\Users\Jason\Projects\7d2d\MapEditor` currently holds only `docs/`. It isn't a git repo yet.

## Approach
A direct-output world editor. It keeps its own editable project format and **exports** finished game world folders. Game assets (stamps, prefabs, biome colours, rwgmixer) are read at runtime from the user's game install and never bundled. Game behaviour (stamp blending, road grading, prefab Y placement) is **reimplemented** in the editor's own code; no game code is included.

### Runtime / tooling
- **.NET 10 (LTS)**, not .NET 8. .NET 8 reaches end of support in Nov 2026. The machine has SDK 9.0.203, so the .NET 10 SDK must be installed first.
- NuGet packages (all MIT): CommunityToolkit.Mvvm, SkiaSharp + SkiaSharp.Views.WPF (canvas and PNG I/O), FastNoiseLite (single-file noise), xUnit.
- Packaging: self-contained win-x64, with a Velopack installer and auto-update.

### Solution layout
```

  Ops/        Brushes (raise/lower/smooth/flatten/noise), StampOp (RWG lerp/additive blend), BiomePaint,
              WaterFill (flood below a level → splat4), RoadRaster + RoadGrade, PrefabPlacer (footprint flatten, median+YOffset)
  Undo/       tile-snapshot undo stack
  Validate/   spawn count, trader presence, prefab overlap/water/slope warnings
src/MapEditor.App/       net10.0-windows WPF, MVVM
  Views: MainWindow (canvas + layer panel + tool panel + properties), NewWorldDialog, PrefabBrowser, ExportDialog, Settings
  Canvas: MapCanvas (SKElement); TileRenderCache (mip pyramid of composited tiles: hillshade + biome tint + roads/water/radiation overlays; prefab footprints and spawns drawn as vectors)
src/MapEditor.Cli/       headless verbs for testing: roundtrip, export, info
tests/MapEditor.Core.Tests/
```

### Data model notes
- Height is stored as **ushort**, the same as the file (8k = 128 MB, 16k = 512 MB). Ops convert to float per tile. Biome is a byte index at W/8. Roads and water are byte layers at W. Radiation is a byte layer at W/32.
- Roads are kept as **vector polylines** (type, width) and rasterised on change or export, so they stay editable. Imported worlds bring their roads in as a raster "legacy roads" layer.
- `.7dmap` project = a zip with `project.json` (size, settings, prefabs, roads, spawns) plus compressed layer blobs.
- Export writes all game files, flips PNGs to north-up, and copies `main.ttw` from a world generated by the game version. It removes stale `*_processed*` and `checksums.txt` files. It can install straight into `%APPDATA%\7DaysToDie\GeneratedWorlds`.

## Decided
- **Town placement (2026-10-17):** a town's 150 m cells now start at the corner the drag starts from, not at the world's grid, so a town drawn against a road sits against it. The drag snaps to whole cells, shows them while dragging, and turns red with a note when it holds none. Street tiles placed by hand follow the grid of the nearest street tile (`PrefabPlacer.TileGridOffset`). RWG keeps a world-wide grid, but a loaded world only lists each prefab's position, so the game doesn't need it.
