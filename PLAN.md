# Plan: 7 Days to Die map editor (Windows desktop app)

## Context
The research (`docs/RWG-Research.md`) showed that a 7D2D world is just a folder of files: `dtm.raw`, `biomes.png`, `splat3.png`, `splat4.png`, `radiation.png`, `prefabs.xml`, `spawnpoints.xml`, `map_info.xml` and `main.ttw`. The game processes this folder itself on first load. So a standalone editor can produce playable maps without the in-game generator (RWG) or the biome-brush mod.

Decisions so far:
- **Public release.**
- **C# + WPF.**
- **Independent of biome-brush.**
- **v1 supports both** editing an existing world and authoring one from scratch.

`C:\Users\Jason\Projects\7d2d\MapEditor` currently holds only `docs/`. It isn't a git repo yet.

## Approach
A direct-output world editor. It keeps its own editable project format and **exports** finished game world folders. Game assets (stamps, prefabs, biome colours, rwgmixer) are read at runtime from the user's game install and never bundled. Game behaviour (stamp blending, road grading, prefab Y placement) is **reimplemented** from the research notes. Decompiled code is a reference only and is not copied in.

### Runtime / tooling
- **.NET 10 (LTS)**, not .NET 8. .NET 8 reaches end of support in Nov 2026. The machine has SDK 9.0.203, so the .NET 10 SDK must be installed first.
- NuGet packages (all MIT): CommunityToolkit.Mvvm, SkiaSharp + SkiaSharp.Views.WPF (canvas and PNG I/O), FastNoiseLite (single-file noise), xUnit.
- Packaging: self-contained win-x64, with a Velopack installer and auto-update.

### Solution layout
```

  Ops/        Brushes (raise/lower/smooth/flatten/noise), StampOp (RWG lerp/additive blend), BiomePaint,
              WaterFill (flood below a level → splat4), RoadRaster + RoadGrade, PrefabPlacer (footprint flatten, median+YOffset)
  Undo/       tile-snapshot undo stack
  Validate/   spawn count, trader presence, prefab overlap/water/slope warnings
src/MapEditor.App/       net10.0-windows WPF, MVVM
  Views: MainWindow (canvas + layer panel + tool panel + properties), NewWorldDialog, PrefabBrowser, ExportDialog, Settings

src/MapEditor.Cli/       headless verbs for testing: roundtrip, export, info
tests/MapEditor.Core.Tests/
```

### Data model notes
- Height is stored as **ushort**, the same as the file (8k = 128 MB, 16k = 512 MB). Ops convert to float per tile. Biome is a byte index at W/8. Roads and water are byte layers at W. Radiation is a byte layer at W/32.
- Roads are kept as **vector polylines** (type, width) and rasterised on change or export, so they stay editable. Imported worlds bring their roads in as a raster "legacy roads" layer.
- `.7dmap` project = a zip with `project.json` (size, settings, prefabs, roads, spawns) plus compressed layer blobs.
- Export writes all game files, flips PNGs to north-up, and copies `main.ttw` from a world generated by the game version. It removes stale `*_processed*` and `checksums.txt` files. It can install straight into `%APPDATA%\7DaysToDie\GeneratedWorlds`.

## Milestones
1. **Scaffold**: git init, solution and projects, settings that find the game install, CI build (GitHub Actions).
2. **Format I/O + round-trip**: WorldReader/WorldWriter and the CLI `roundtrip` verb. Tests cover byte-identical `dtm.raw`, PNG orientation (the water-vs-height check from the research), and prefab/spawn XML. Then a manual in-game load of a re-exported world.
3. **Viewer**: open a world; pan and zoom up to 16k; layer toggles; hillshade; a cursor readout in game coordinates and height; minimap.
4. **New world + terrain**: a New World dialog (size as a multiple of 512, base height, optional noise, land or water border using the game's border stamps). Brushes, a stamp tool using `Data/Stamps` with the RWG blend, undo/redo, heightmap RAW import/export.
5. **Paint layers**: biomes (game colours from `biomes.xml`), radiation, water flood-fill.
6. **Roads**: polyline tool (asphalt or gravel, with width), rasterisation to splat3, grading that smooths the terrain under the road core and feathers the shoulders.
7. **POIs & spawns**: prefab browser (filters on tags, tier, size, zoning; preview jpg), place/rotate/move, footprint flatten and feather, Y = median height + YOffset, warnings. Spawn point tool. Street-tile (`rwg_tile_*`) placement for hand-built towns.
8. **Project save, validation, export, release**: `.7dmap` save/load with autosave, validation panel, Export dialog, Velopack installer, README/docs. Release v1.0 comes after M9.
9. **UI polish (Paint-style layout)**: rework the main window so it is as simple to use as Microsoft Paint.
   - **Title bar and menus:** "World name - MapEditor"; File / Edit / View menus; quick-access Save, Undo and Redo icons beside them.
   - **Ribbon toolbar** across the top, replacing the side tool panel. Groups have a label underneath: Selection; Terrain (raise, lower, smooth, flatten, noise, stamp); Paint (biome, radiation, water); Roads; POIs (prefabs, town, spawns); Layers (a drop-down of layer toggles). Each tool has an icon button with a tooltip and its shortcut key, and the active tool is highlighted.
   - **Palette group**, like Paint's colours: biome swatches in the game colours from `biomes.xml`, road types (asphalt, gravel), and radiation levels. The current choice is shown as a large swatch. The swatches change with the active tool.
   - **Vertical sliders on the left edge** for brush size and strength/opacity, like Paint's size and opacity sliders, with values shown while dragging.
   - **Context options:** the controls for the active tool (shape, rotation, falloff, township, seed, and so on) appear in a collapsible strip under the ribbon instead of a long side panel.
   - **Status bar along the bottom:** cursor position in game coordinates and height, the biome under the cursor, world size (e.g. 8192 × 8192), the selection size, and a zoom slider with −/+ buttons, a zoom % drop-down and "Fit to window".
   - **Canvas:** centred on a dark backdrop with a clear edge around the world; the minimap is a toggle in View.
   - **Look:** follow the Windows light/dark theme; consistent icon set (Segoe Fluent Icons); keyboard access to every control; works at 100–200% display scaling and down to 1366×768.
   - Done when a new user can find and use every tool without reading docs, and all existing shortcuts still work. Then ship as v1.0.
10. **v1.1 features** (the user's list, 2026-10-18; design choices made by the user):
   - **Road snapping:**
     - **End snap:** near the end of any road on the map (found in splat3, so it covers RWG roads and opened worlds), the first click snaps to that end. The new road carries on in the old road's direction, with its width and surface.
     - **Angle snap:** a segment within about 5° of 0/90/180/270 snaps to it. Hold Alt to draw freely.
   - **Road width presets:**
     - Asphalt: Highway 18 m (RWG's 4-lane highway), Main street 12 m, Town street 9 m, Residential 6 m.
     - Gravel: Country road 9 m (RWG's 2-lane country road), Track 4.5 m (one lane).
     - Picking one sets the surface and the width. The slider still sets any width.
   - **Trader tool** in the Build group: picks a random vanilla trader, which can be changed from a short list, then places it like the Prefab tool (ghost, rotation, flatten).
   - **Remove a proposed link road:** in a town plan, clicking a link road turns it off, leaving its exit unjoined; clicking again brings it back.
   - **Resize the town box:** after the drag, drag an edge or corner of the box to resize it in 150 m tile steps, and the town replans.
   - **POI snapping to tiles** (added later the same day): a POI or trader being placed or dragged snaps to the edges of street tiles nearby (against a side, flush inside, or lined up with the sides); it does not snap to other POIs. Dropped so it covers another POI's centre, it replaces that POI (shown red) in the same undo step. Alt turns snapping off.
   - **Roads meet POIs and towns level** (from the user's in-game testing): a road placed first used to end in a step up or down where a POI, trader or town was built against it, since the footprint is flattened to its own ground and the road is resmoothed back to its old height. Now `RoadOp.RampToFootprints` ramps the road that touches the footprint (within 3 m) onto its ground, over 40–150 m (25 m per metre of height), with the ground beside the road following. Other roads nearby are left alone.
     - **Revisit (the user asked):** the alternative is for the POI or town to take the road's height instead, or a per-placement option between the two.
   - **Select tool replaces Pan** (the user's request): click a POI, trader, street tile or spawn point to select it (parts aren't picked); drag to move, Q/E, PgUp/PgDn, Del as before. A drag on empty ground pans, as Pan did. Shortcut V. The Prefabs and Spawn tools keep their own selecting (the user's choice). New worlds start on Select.
   - **Stamp preview:** the Stamp tool's cursor shows the stamp from above (`StampPicture`: shaded heights, see-through where its alpha fades, blue for its water), turned and sized as it will be stamped.
   - **Themed message boxes:** every message box is now `ThemedMessageBox` (same arguments as `MessageBox.Show`), in the Fluent theme. Open, save and folder pickers stay the Windows ones, which follow the Windows theme.
   - **Updates on:** the repo went public on 2026-10-18, so `Updates.cs` now uses Velopack's `GithubSource` for this repo. Builds with a pre-release version (e.g. 1.1.0-beta) also take later pre-releases. Copies of 1.0.0 and 1.1.0-beta have no feed, so the first release with this is the first that updates itself.
   - Done when each works in the editor and in a new game. Then ship as v1.1.0.
   - **Status (2026-10-18):** all six built, with tests for finding road ends (`RoadEndTests`) and for POI snapping and covering (`PrefabTests`). Not yet checked by the user. The Trader tool's shortcut is A; Alt+click places without snapping.

Each milestone ends with a world that loads in game.

## Decided
- **Town placement (2026-10-17):** a town's 150 m cells now start at the corner the drag starts from, not at the world's grid, so a town drawn against a road sits against it. The drag snaps to whole cells, shows them while dragging, and turns red with a note when it holds none. Street tiles placed by hand follow the grid of the nearest street tile (`PrefabPlacer.TileGridOffset`). RWG keeps a world-wide grid, but a loaded world only lists each prefab's position, so the game doesn't need it.
