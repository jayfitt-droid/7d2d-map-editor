# 7 Days to Die map generation: research notes

Sources: the game install at `C:\7D2D\Custom\v3.3`, the decompiled `Assembly-CSharp` in `D:\dotPeek Test\Assembly-CSharp` (namespace `WorldGenerationEngineFinal`), the `biome-brush` mod in `D:\biome-brush`, and the generated worlds in `%APPDATA%\7DaysToDie\GeneratedWorlds`.

## 1. The key finding: a world is just files

The game never needs the generator at play time. A world is a folder of plain files. The game loads it through `ChunkProviderGenerateWorldFromRaw`, and on first load it builds its own caches (`dtm_processed.raw`, `splat3_processed.png`, `splat4_processed.png`, `*_half.png`, `checksums.txt`).

So a desktop app can make a playable map by **writing these files directly**. It doesn't need to run or hook the game. The in-game generator (RWG) is one way to produce the files; an editor can be another.

## 2. World folder format

`W` is the world size in metres, for example 6144, 8192 or 10240. It must be a multiple of 512 (2048 is the smallest RWG size).

| File | Format | Notes |
|---|---|---|
| `dtm.raw` | `W×W` uint16 little-endian, no header | height = value / 257 (0–255 m). **Row 0 = south edge** (z = −W/2). The loader clamps to 250. |
| `biomes.png` | RGBA, `W/8 × W/8` (RWG); any size works, scale = W / width | Exact colours from `biomes.xml` `biomemapcolor`: forest `#004000`, burnt `#BA00FF`, desert `#FFE477`, snow `#FFFFFF`, wasteland `#FFA800`. |
| `splat3.png` | RGBA32, `W×W` | Roads: **R=255 asphalt (highway)**, **G=255 gravel (country road)**. The game smooths and processes it on load. |
| `splat4.png` | RGBA32, `W×W` | Water: **B = water surface height** (RWG writes 30, its `WaterHeight`), A=0. Pixels with B>0 where the terrain is below the surface become water. |
| `radiation.png` | RGBA, `W/32 × W/32` | R>0 = radiation zone. RWG marks the map border this way. |
| `prefabs.xml` | `<prefabs><decoration type="model" name="…" position="x,y,z" rotation="0-3"/>` | `position` = **bounding-box min corner** in world coords (centre of map = 0,0). `y` = ground height + the prefab's `YOffset`. Includes town street tiles (`rwg_tile_*`). |
| `spawnpoints.xml` | `<spawnpoint position="x,y,z" rotation="0,deg,0"/>` | World coords, centred. RWG aims for 12. |
| `map_info.xml` | `MapInfo` properties | `HeightMapSize="W,W"`, `Scale=1`, `RandomGeneratedWorld=true`, `FixedWaterLevel=false`, plus informational `Generation.*` values. |
| `main.ttw` | small binary `WorldState` | Generic: game version + a GUID, nothing world-specific. **Copy one from a world generated by this game version.** |
| `water_info.xml` | optional | Used by hand-made worlds (Navezgane). RWG doesn't write it. |

**Orientation (checked against "Vafuru Valley"):** `dtm.raw` row 0 is south. PNGs are stored **north-up** (image row 0 = north). In-memory arrays are `x + z*W` with z=0 at the south, so the editor must flip vertically when reading or writing PNGs. 100% of water pixels lined up with low terrain only after the flip.

Coordinate conversion: `worldX = pixelX − W/2`, `worldZ = rawRow − W/2`.

What the game adds on load, so the editor doesn't have to: it copies each prefab's own terrain heights and terrain textures into the heightmap and splats, adds biome "bluffs", turns road pixels into road surface, and computes water chunks.

## 3. How RWG generates a world (`WorldBuilder.GenerateTask`)

The seed is `WorldSeedName.GetHashCode() + WorldSize`. That is Mono's string hash, and every sub-step re-seeds from it. Exact RWG reproduction outside the game is therefore possible but fragile, and the editor shouldn't depend on it.

1. **Biome tiles** (`GenerateBiomeTiles`): a coarse grid of 256 m tiles (`W/256` square). Biome weights (forest 13, burnt 18, desert 22, snow 23, wasteland 24 by default) set tile counts. Each biome gets a seed point by layout: `CenterForest`, `CenterWasteland`, `Circle`, `Circle2` or `Line`. Then it grows ring by ring (`FindBiomeEmptyAndSet`) into empty neighbours.
2. **Terrain tiles** (`GenerateTerrainTiles`): each 256 m tile becomes plains, hills or mountains in proportion to the Plains/Hills/Mountains weights (4/4/2). Hills come in 2×2 blocks. Mountains chain into neighbours 80% of the time. Wasteland can't hold mountains.
3. **Base stamps** (`GenerateBaseStamps`): the heightmap starts flat at 35 m. Each map edge gets either `land_border` stamps or `water_border` stamps (ocean edge), chosen by a random 4-bit `BorderWaterMask`. `biomeDest` is filled by stamping the `filler_biome` mask over each tile's biome colour, which gives organic edges.
4. **Terrain stamps** (`GenerateTerrainFromTiles` for plains/1024, hills/512, mountains/256): per tile it picks a stamp named `{biome}_{terrain}_NN` or `{terrain}_NN` from `Data/Stamps`. Scale, cluster count, radius and strength come from `rwgmixer.xml`. The first stamp is a full lerp toward the stamp's height. Later ones are additive at 45% strength. Mountains with `use_biome_mask` also paint their alpha into the biome map.
5. **Stamp blending** (`StampManager.DrawStamp`): a stamp file has R = height (×255), A = alpha mask, B = water mask. For each destination pixel it samples bilinearly with rotation and scale, then `h = lerp(h, stampH, alpha*strength)`, or `h += stampH*alpha*strength` when additive. Heights are clamped to at least 2.
6. **Towns** (`TownPlanner.Plan`): works on a 150 m street-tile grid. For each township type in `rwgmixer.xml` (count + tile range), it finds a valid area in an allowed biome. A tile is valid if it has no water, mixed biome, radiation, steep slope or mountain. It lays out streets, grows outskirt districts, and assigns districts (`DistrictPlanner`: downtown, commercial, industrial, residential, rural, gateway…). Each tile gets an `rwg_tile_*` road prefab.
7. **Terrain features** (`generateTerrainFeature`): lakes, rivers, canyons and craters are single large stamps on free tiles. Water stamps also fill the water layer.
8. **POI placement** (`Township.SpawnPrefabs`, `WildernessPlanner`): street-tile prefabs carry POI markers. Markers are filled with prefabs scored by size, zoning, tags and biome (`PrefabManager.getScoreForPrefab` plus `prefab_spawn_adjust` rules). A wilderness POI sits on one free tile if the terrain under it varies by ≤ 11 m. It's placed at the median height + `YOffset`, then the area is smoothed.
9. **Roads** (`HighwayPlanner`, `WildernessPathPlanner`): A* on a 10 m grid (`PathingUtils`) with height cost (max step 11–12 m). Highways link town exits to the nearest towns. Gravel roads link wilderness POIs to the network. Roads are drawn as ids, then converted to splat3 colours.
10. **Spawns**: up to 12 player spawns in forest wilderness tiles within 900 m of a trader.
11. **Road smoothing** (`SmoothRoadTerrainTask`): 6 passes level the road cores, then 30 weighted passes feather the shoulders. POI footprints are masked out.
12. **Water finalize**: water stays only where terrain − 0.5 ≤ the water height.

Config inputs: `Data/Config/rwgmixer.xml` (per-size stamp, feature and township rules), `biomes.xml`, `Data/Stamps/*.raw|png`, and prefab metadata in `Data/Prefabs/**/*.xml` (`PrefabSize`, `YOffset`, `RotationToFaceNorth`, `Tags`, `Zoning`, `AllowedTownships`, `DifficultyTier`, POI markers).

## 4. What biome-brush does

It's a Harmony mod that adds a painting tab to the in-game world generator. The user paints 512×512 layers: biomes, height levels (hills, mountains, peak), roads, carve/dig, elevation, no-POI zones, districts, "only" zones, edge borders. They also place markers (cities with size and type, craters, spawns, specific POIs with rotation). The mod then lets RWG run and **overrides each phase as it goes**. For example, it postfixes `GenerateTerrain` and `GenerateTerrainLast` to write its height, water, crater and edge layers. It patches `TownPlanner` to force cities. It patches `PrefabManager` scoring to filter POIs and swap traders, and `DrawRoads` to inject painted roads. Presets are a versioned binary `.bbp` file (magic `0x42424231`, version 20).

Its limits as a starting point for a desktop editor:
- It works at 512² resolution and leans on RWG's random fill. It nudges the generator rather than authoring a world.
- It's tightly coupled to private RWG internals, so game updates can break it.
- Everything happens inside the game UI.

Its value: it's a proven catalogue of the features map makers want, and its algorithms (shore fields, height levels blurred into terrain, road causeways and bridges) are good references.

## 5. Proposed app

### Approach
A **direct-output world editor**. It authors the world's own files at full resolution and then lets the game process them on first load. Two entry points:
1. **Open an existing world** (generated or pregen): load everything, edit, save as a new world. This gives value soonest. Users can start from an RWG result they nearly like.
2. **New world**: a blank or noise-based heightmap, then build it up with tools.

An optional later bridge: export a `.bbp` preset so biome-brush users can hand a design to RWG.

### Layers (internal model)
- Height: float32 `W×W` (256 MB at 8k), tiled for undo.
- Biome: byte index `W/8 × W/8`.
- Roads: byte `W×W` (none, gravel, asphalt).
- Water: byte `W×W` (surface height).
- Radiation: byte `W/32²`.
- Prefabs: a list of {name, position, rotation} plus metadata read from `Data/Prefabs`.
- Spawns: a list of points.

### Tools, in phases
1. **Viewer / round-trip** (proves the format): open a world, show a hillshaded heightmap with biome, road, water and POI overlays, pan and zoom at 8k–16k, save an unchanged copy that the game loads.
2. **Terrain**: raise/lower, flatten-to-height, smooth, and noise brushes. A **stamp** tool that uses the game's own `Data/Stamps` files with the RWG blend maths (§3.5). Heightmap import/export (16-bit PNG/RAW).
3. **Paint**: biomes at 8 m resolution, radiation, water bodies (flood-fill below a level, which gives correct shorelines automatically).
4. **Roads**: draw polylines with width and type, rasterise them to splat3, and grade the terrain under them (a port of the §3.11 smoothing). Optional A* auto-routing between points.
5. **POIs**: a prefab browser (name, size, tags, tier, preview `.jpg`), place, rotate, snap. On place, flatten and feather the footprint, compute `y` from the median + `YOffset`, and warn on overlaps, water or slope. Then town street tiles (`rwg_tile_*`) for building towns.
6. **Validation & export**: check spawns, traders and biome coverage. Write all files, copy `main.ttw` from a template, delete stale `*_processed` and `checksums.txt` so the game reprocesses, and install into `GeneratedWorlds` or a server's `Data/Worlds`.

### Tech stack (recommendation)
**C# / .NET 8 + WPF** (Windows-only, as asked), with **SkiaSharp** or a Direct3D 11 surface for the large canvas.
- The game's code is C#, so the stamp blending, road smoothing and prefab-placement rules can be reimplemented closely.
- The data is large (an 8k float heightmap is 256 MB; 16k is 1 GB). Render from tiled, mip-mapped caches and do brush work with `Span<T>` and SIMD on background threads. Use a GPU compute path later if brushes feel slow.
- Read `Data/` (stamps, prefabs, `biomes.xml`, `rwgmixer.xml`) from a configurable game install path, so modded games work too.

Note: decompiled game code is a reference for behaviour. Rewrite the logic rather than pasting it, especially if the app will be distributed.

### Verified
- 2026-10-16: a world written by the editor (a round-trip of the v3.3-generated "Mezawoku Mountains", keeping its own `main.ttw`, with all `*_processed`/`checksums.txt` caches removed) loads and plays correctly in v3.3.
- The game warns "map from an old version" when `map_info.xml` `GameVersion` (for example `V.3.30.18`) has a different major version from the running game (`XUiC_NewGame`, `EqualsMajor`). A world with no `GameVersion` property (as in the shipped Pregen worlds) gets no warning.
